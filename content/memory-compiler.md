# A01｜記憶體與編譯器全圖解

定位：第1、3、4、8、10、15、20章的底層補充。閱讀前至少做完第4章所有權教材。

## 一、Rust 在解決的根本矛盾

任何程式需要資料、計算與資源；資料必須在某一段時間有效，運算必須符合型別，資源必須在不用時回收。若語言允許任意指標、任意釋放與任意並行修改，會有高效但極難排查的錯誤。若一切交給執行時追蹤，也可能帶來額外執行成本或延遲。

Rust 的核心折衷：用編譯期的型別、所有權、借用、生命週期檢查消除大量記憶體安全風險，同時保留必要時進入底層操作的能力。

## 二、先畫出 CPU 與記憶體關係

CPU 執行機器指令；暫存器存放計算中的少量資料；主記憶體保存程式碼與資料；作業系統管理程序可使用的虛擬位址空間。堆疊（stack）常管理函式呼叫相關資料，堆積（heap）適合生命週期或大小需動態處理的配置。

但「Rust 所有局部變數都在 stack」是過度簡化：編譯器可能把值保存在暫存器、消除配置、合併或移動暫存結果。學習時用 stack/heap 主要建立資源存活模型，不是預測每個位元組的實際位置。

## 三、String 的概念性構造

String 的值一般可視為三項資訊：ptr（緩衝區位置）、len（已使用位元組數）、capacity（可容納位元組數）。實際結構布局與編譯器最佳化不應當成公開穩定 ABI。

例如 String::from("abc") 要擁有自己的資料；clone() 會產生另一份擁有權，適用時配置新的資料緩衝；移動 String 則轉移所有權，保證原綁定不能再用。

時間線：

T0：let a = String::from("abc"); a 有擁有權。

T1：let b = a; 所有權移至 b，a 失效。

T2：b.push('!'); b 依可變權限修改。

T3：b 離開作用域，執行必要清理，所擁有的記憶體可被釋放。

注意：所有權語意不代表機器碼一定複製固定三個欄位，編譯器可能最佳化。

## 四、借用相容性推導

當一段資料有活躍的共享借用 &T 時，其他可修改或移動該資料的動作可能使引用觀察到不穩定狀態，因此受到限制。同一期間的 &mut T 則要求獨占存取，用來保證安全修改。

```rust fragment
let mut s = String::from("A");
let r = &s;
println!("{r}");
s.push('B');
```

這段可以通過，因 r 最後一次使用已經結束。若把 println!("{r}") 搬到 push 後，借用重疊，就會被拒絕。

## 五、生命週期是關係證明，不是資源延壽

```rust fragment
fn choose<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() > b.len() { a } else { b }
}
```

這個簽名告訴呼叫者：回傳值可能借用 a 或 b，所以呼叫端必須維持被選來源有效。編譯器使用約束推導可安全使用的範圍，而不是為 a、b 實際計秒。

## 六、從原始碼到可執行檔，誰做了什麼？

簡化流程：詞法與語法解析 → 名稱解析與型別檢查 → 中介表示與借用分析 → 最佳化與代碼生成 → 連結 → 執行檔 → 作業系統載入 → CPU 執行。

Rust 編譯器內部會使用 HIR、MIR 等表示，後端可使用 LLVM 等程式碼產生器；這是概念性流程，不承諾各分析階段永遠以單一線性順序執行。

cargo check 著重主要語意檢查而通常不產生一般執行檔；cargo build 才進一步完成建構；cargo run 視需要建構並啟動。

## 七、沒有 GC 是否等於絕不洩漏？

不等於。Rust 允許透過 std::mem::forget、Box::leak 或 Rc 循環等方式產生洩漏；安全 Rust 的主要承諾是避免某類無效記憶體存取與資料競爭，不是保證所有資源一定回收。

即使程式記憶體安全，也可能邏輯錯誤、死鎖、耗盡記憶體、回傳錯誤結果或留下外部副作用。

## 八、為什麼不能隨意將物件指標交給 C？

Rust 與 C 的型別布局、別名和生命週期契約可能不同。對外部 API 要驗證記憶體是否有效、誰配置與誰釋放、ABI、對齊、字串格式、同步策略。#[repr(C)] 只解決一部分布局問題。

## 九、實驗設計

實驗1：在 String move 後使用舊綁定，閱讀 E0382；改用 &str 借用，不要立刻 clone。

實驗2：先拿 &v[0] 再 push，並在 push 後閱讀舊參考，預測編譯器拒絕的原因。

實驗3：寫 fn bad() -> &str { let s = String::from("x"); &s }，修成回傳 String。

實驗4：用 std::mem::size_of::<usize>() 和 size_of::<&str>() 觀察目標平台差異；不要把觀察結果誤當成所有平台永久固定的標準。

## 十、驗收標準

能自行畫出擁有者、借用者、配置釋放時間線。能說明 move/clone/Copy/&/&mut/Drop 的差異。能區分靜態型別檢查、執行時借用檢查與 unsafe 的信任邊界。

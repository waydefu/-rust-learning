# Rust 語法｜從零到實作

*課程導覽、教學原則、章節路線與學習進度*

課程基礎：《Rust 程式設計語言》繁體中文版（依原書章節順序）；關鍵技術與語法差異以 Rust 官方最新版文件交叉核對。

## 學習方法

每一個新概念都按五步走：①先問它解決什麼問題；②從電腦運作或程式邏輯推導原因；③用恰當比喻建立直覺；④逐行拆解可執行範例；⑤透過小練習、錯誤案例與自我驗收確認理解。

抽象名詞初次出現時，先以淺白語言解釋，再對應正確術語。比喻不是技術定義：會同時交代比喻在哪裡失效，避免建立錯誤直覺。

預設繁體中文；程式碼與官方專有名詞保持原樣。尊重原書先後順序，但遇到必要先備知識會即時補充；沒有理解就不為了進度硬跳章。

### 零基礎閱讀標準

教材以從未寫過程式、甚至還不知道 CPU 和記憶體是什麼的讀者為起點。目標不是將技術內容幼稚化，而是讓每個複雜概念都能從已理解的簡單概念一步一步推導。所有主課程及延伸教材的後續改寫，採用以下共同標準：

1. **先說來龍去脈。** 從具體生活情境或程式需求開始，交代原本怎麼做、遇到什麼問題、為何需要新的機制；再說 Rust 的解法與取捨。不為了好記而編造歷史。
2. **不偷渡先備知識。** 新名詞第一次出現時，用淺白中文解釋、附上英文正式術語；新符號先說如何讀、在哪裡使用、代表什麼。尚未學過的必要概念先給足以理解本章的解釋，並連到深入章節。
3. **建立直覺再精確化。** 優先使用日常生活、遊戲與具體資料流的例子；再映射到真實程式行為，明確說明比喻不適用的情況。圖解是語意模型時，不把它當成實際硬體位址或編譯器內部狀態。
4. **程式碼不是答案圖片。** 使用短小、獨立或清楚標示接續關係的範例；重要的新語法逐行解釋，給出預期結果、編譯失敗原因及最小修正，讓讀者能自己重現。
5. **每次只增加必要的難度。** 先學會一個概念，再比較容易混淆的概念，最後進入進階細節。不要用另一個尚未解釋的術語來解釋第一個術語。
6. **用證據確認理解。** 先預測結果、再執行、再修改、最後解釋原因。提示、錯誤診斷與解答服務於理解；完成閱讀不等於掌握。Rust 範例沿用本站驗證標記及固定工具鏈，避免讓讀者練到錯誤的範例。

每章完成後，讀者應能回答：這個概念解決了什麼問題？沒有它會怎樣？Rust 怎麼解決？我怎麼看懂並使用它？我能否修改範例並解釋結果？如果只能背定義或複製程式碼，就還有需要補強的地方。

進階原理不必刪掉，但應清楚區分「現在就要懂」與「之後再深入」。同一章的基本路線應不依賴進階補充才能讀通。這些是教材編寫與驗收的目標，不代表已經由所有年齡層讀者實測。

### 彩色教學方塊怎麼讀？

- **來龍去脈（藍色）**：先知道問題從哪裡來。
- **生活比喻（紫色）**：把陌生概念連到已知經驗。
- **程式拆解（青色）**：跟著程式的每個重要步驟。
- **常見陷阱（橘色）**：注意容易誤解或出錯的地方。
- **動手驗收（綠色）**：先猜結果、再實作與解釋。

每章五種方塊分布於相關段落。顏色只是輔助定位，文字標籤才是意義；深色模式仍可閱讀。想回顧重點時可以先找方塊，再回正文補足原理。
